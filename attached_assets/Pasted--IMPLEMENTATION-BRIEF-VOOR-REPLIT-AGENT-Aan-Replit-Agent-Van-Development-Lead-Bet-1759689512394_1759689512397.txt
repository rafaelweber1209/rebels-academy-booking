### 1. API & TECHNISCHE VEREISTEN

**OpenAI Responses API Integratie**:
- Endpoint: `POST https://api.openai.com/v1/responses`
- Model: `gpt-5-nano`
- Enable streaming: `stream: true`
- Reasoning effort: `medium`
- Text verbosity: `low`

**Authentication**:
- OpenAI API Key benodigd via environment variable: `OPENAI_API_KEY`
- **BELANGRIJK**: API key NOOIT client-side exposen
- Implementeer server-side proxy (API route, edge function, of backend endpoint)

**Request Structuur**:
```json
{
  "model": "gpt-5-nano",
  "stream": true,
  "reasoning": { "effort": "medium" },
  "text": { "verbosity": "low" },
  "tools": [
    {
      "type": "file_search",
      "vector_store_ids": [
        "vs_68cdba5cb0688191856f589a70ca2439",
        "vs_68d95a9ec860819193d3126cb51f5041"
      ]
    }
  ],
  "input": [
    { 
      "role": "system", 
      "content": [{ "type": "input_text", "text": "[jouw system prompt]" }] 
    },
    { 
      "role": "user", 
      "content": [{ "type": "input_text", "text": "[user vraag]" }] 
    }
  ],
  "previous_response_id": "[optional - voor conversation context]"
}
```

**Headers**:
```
Authorization: Bearer {OPENAI_API_KEY}
Content-Type: application/json
```

**Response Handling**:
- Response komt via Server-Sent Events (SSE) stream
- Parse SSE format: `data:` lines gescheiden door blank lines
- Extract text chunks uit events voor real-time display
- Capture `response_id` uit final event voor conversation continuity
- Stop bij `[DONE]` event

### 3. CONVERSATION CONTEXT (OPTIONEEL MAAR AANBEVOLEN)

**Previous Response ID Pattern**:
Voor betere multi-turn conversations:
1. Na elke response, sla `response_id` op uit het laatste SSE event
2. Bij volgende user message, stuur deze mee als `previous_response_id` in request
3. Dit geeft conversatie geheugen zonder volledige history te sturen
4. Bij nieuwe conversation: laat `previous_response_id` weg of null

**Message Storage**:
- Sla messages lokaal op (browser localStorage)
- Simpele structuur: `{ conversationId, messages: [{text, isUser, timestamp}] }`
- Support voor "nieuwe conversatie" button (clear messages, reset response_id)

### 6. SECURITY & BACKEND

**API Key Protection**:
Implementeer een van deze opties:

**Optie A - Next.js API Route**:
```javascript
// pages/api/chat.js
export default async function handler(req, res) {
  // Optioneel: rate limiting
  // Optioneel: user authentication
  
  const response = await fetch('https://api.openai.com/v1/responses', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify(req.body)
  });
  
  // Stream response door naar client
  response.body.pipe(res);
}
```

**Optie B - Cloudflare Worker**:
- Deploy lightweight edge function
- Minimale latency
- Built-in rate limiting

**Optie C - Express Backend**:
- Dedicated API endpoint
- More control over authentication/logging

**Rate Limiting**:
- Implementeer limit per IP of session (bijv. 20 messages per uur)
- Voorkom abuse en cost explosions
- Toon friendly error bij limit reached
